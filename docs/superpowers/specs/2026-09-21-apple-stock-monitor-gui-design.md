# Apple 商店库存监控 GUI 设计文档

- 日期：2026-09-21
- 项目：apple-stock-monitor
- 阶段：CLI 已完成（17 个测试全绿），本设计覆盖 GUI 实现

## 1. 目标与范围

为现有 CLI 监控工具提供原生 macOS 桌面 GUI，核心功能：

- 监控型号管理（搜索、添加、移除、查看库存状态）
- 中港直营店库存实时展示（按门店列表 + 状态色标）
- 到货推送开关（macOS 桌面通知 + 可选 Bark）
- 手动刷新与自动轮询

**范围外**：不重写 CLI、不修改数据层接口（fetcher/parser/models/notifier/state/catalog 全部复用）、不做更多地区（美/日）扩展。

## 2. 技术栈

- **PySide6（Qt for Python）**：原生桌面窗口，深色 QSS 样式还原科技感 Dashboard。
- Python 3 + requests（现有依赖），GUI 需新增 `PySide6` 依赖。
- 复用现有模块：`fetcher`（拉取）、`parser`（解析）、`catalog`（模糊搜索）、`models`（WatchItem/StockResult）、`notifier`（通知）、`state`（历史状态）。

## 3. 视觉风格（方案 B · 科技感 Dashboard）

- 主背景：深色渐变 `linear-gradient(135deg, #0d0f1a, #1a1f2e)`
- 强调色：霓虹蓝 `#4cc2ff`（渐变按钮 `#4cc2ff → #2a7fff`）
- 状态色：
  - 有货 `#30d158`（绿）
  - 无货 `#ff453a`（红）
  - 即将到货/其他 `#ffd60a`（黄）
- 文字：主 `#e8eaf0`、次 `#8b90a3`
- 卡片：`rgba(255,255,255,0.03~0.06)` 背景 + 1px `rgba(255,255,255,0.06~0.08)` 边框，圆角 10px

## 4. 窗口布局

```
┌────────────────────────────────────────────────┐
│ STOCK MONITOR   [中国区] [香港区]        ● 运行中 │  ← 顶部栏
├────────────────────────────────────────────────┤
│ 当前监控型号: iPhone 18 Pro 512GB   [更换]        │  ← 型号卡片
├────────────────────────────────────────────────┤
│ [3 有货]  [2 无货]  [1 即将到货]                 │  ← 统计条
├────────────────────────────────────────────────┤
│ Apple 北京三里屯          ● 有货                  │
│ Apple 北京朝阳大悦城      ● 无货                  │
│ Apple 香港中环            ● 即将到货              │  ← 门店库存列表
│ ...                                             │
├────────────────────────────────────────────────┤
│ 到货推送 [开关]  Bark[key]    [刷新] 上次 12:30   │  ← 底部栏
└────────────────────────────────────────────────┘
```

### 4.1 顶部栏

- 左侧 `STOCK MONITOR` 标题（`STOCK` 霓虹蓝 + `MONITOR` 白色）
- 中部地区切换胶囊按钮：中国区（激活态霓虹蓝描边）/ 香港区
- 右侧运行状态灯：`● 运行中`（绿）/ `● 已停止`（灰）

### 4.2 监控型号卡片

- 显示当前选中的监控型号名称（从 `WatchItem.label` 读取，用户友好中文名）
- 「更换」按钮：打开型号选择对话框
- 地区切换时自动切换为该地区当前配置的监控型号

### 4.3 统计条

- 三个等宽数字卡片：有货门店数 / 无货门店数 / 即将到货门店数
- 数字大号加粗，颜色对应状态色
- 数据来源：当前地区 + 当前型号的最近一次查询结果

### 4.4 门店库存列表

- 每行一家直营店：左侧店名，右侧状态（`● 有货` / `● 无货` / `● 即将到货`）
- 行按状态排序：有货 → 即将到货 → 无货
- 门店数据来自 `fetcher.fetch_stores(region)`（24h 缓存）
- 状态来自 `parser.parse_stock_json` 的 `pickup_display` 字段

### 4.5 底部栏

- **到货推送开关**：主开关控制是否发送通知（桌面通知始终走 `notifier.notify_all`）
- **Bark 配置**：点击展开小输入框填 Bark key（持久化到 config.json `bark.key`）
- **刷新按钮**：立即触发一轮查询（后台线程）
- **上次刷新时间**：显示 `HH:MM`，刷新失败显示红色原因

## 5. 核心交互与数据流

### 5.1 型号选择器（对话框）

1. 用户点击「更换」→ 弹出对话框
2. 对话框含搜索框 + 候选列表
3. 输入时调用 `catalog` 模糊搜索（中文名/英文名/Part Number 均支持）
4. 候选显示型号名 + Part Number，点击选中
5. 选中后写入 config.json watchlist（若该型号不在当前地区配置中则新增，否则切换）
6. 关闭对话框，主窗口刷新库存

### 5.2 库存查询线程

- 使用 `QThread` 后台执行，避免阻塞 UI
- 查询参数：当前地区 + 当前型号 + 该型号关注的店铺列表（空=全部店铺）
- 复用 `fetcher.fetch_stock_json(region, models, store_id)` 与 `parser.parse_stock_json`
- 查询完成后通过 Qt 信号（signal）回传主线程更新 UI

### 5.3 自动轮询

- 启动时读取 config.json `poll_interval_minutes`（默认 10 分钟）
- 使用 `QTimer` 定时触发查询线程
- 每次查询完成后：
  - 若存在库存状态从无货→有货的变化，调用 `notifier.notify_all` 发送通知（受推送开关控制）
  - 更新统计条、门店列表、上次刷新时间

### 5.4 推送开关

- 主开关状态持久化到 config.json（新增 `gui.notify_enabled` 字段，默认 true）
- Bark key 持久化到 config.json `bark.key`（复用现有字段）

## 6. 错误处理

| 场景 | 行为 |
|------|------|
| 网络请求失败（超时/连接错误） | 底部显示红色横幅「刷新失败：原因」，保留上次数据并标记「数据可能过期」 |
| 接口返回结构异常（ParseError） | 同网络失败处理，提示接口可能变更 |
| 型号不在 catalog 中（手动输入） | 型号选择器提示「未找到匹配型号」 |
| 店铺列表拉取失败 | 使用上次缓存的店铺列表，横幅提示 |
